## Background and Locked Decisions

Functional requirement (new): two marker classes, never treated as the same object.

| | Prayer Time Marker | Boundary Time Marker |
|---|---|---|
| Members | fajr, dhuhr, asr, maghrib, isha (+ jumuah replaces dhuhr Friday) | imsak, syuruq, dhuha |
| Adhan / Iqamah / auto-dim | yes / yes / yes | never / never / never |
| State machine | drives all 5 states | never leaves NORMAL; never PRE_ADHAN/ADHAN/IQAMAH_COUNTDOWN/SALAH_DIM |
| Countdown | hero countdown (adhan→iqamah) | opt-in only (`Settings.boundary_countdown`, default off) |
| Frontend level | primary cards + hero | secondary position, never at prayer level |
| Tests | pre-adhan/adhan/iqamah/dim windows | never enter those windows; pointer-only tests |

User-approved decisions (locked for this slice):

1. **Wire spelling stays `dhuhr` / `syuruq`** (PRD/contract spelling); the FR's "dhur/syuruk" are the same names, no rename.
2. **Imsak and dhuha enter the schedule now.** JAKIM's e-solat surface provides 8 markers (portal headings: `IMSAK, SUBUH, SYURUK, DUHA, ZOHOR, ASAR, MAGHRIB, ISYAK`); the adapter (1A-6) maps source spellings (`subuh/zohor/isyak/syuruk/duha/...`) onto backend `MarkerName` values. The mapping table + full ordering rule land in PRD §6.1 now; exact JSON key inventory and calc-mode derivation rules (observed convention: imsak = subuh − 10 min; dhuha = fixed offset after syuruq) are a 1A-6 source-research deliverable.
3. **Contract v1 is amended in place** — no frontend consumer exists (1B-1 unlanded); fixtures + `docs/api-contract.md` + a CHANGELOG migration note ship together, and the versioning section gains an explicit pre-consumer-amendment clause. No `/api/v2`.
4. **Opt-in boundary countdown = gated pointer fields.** `NextEvent`/DTO gain `next_boundary` + `boundary_at` (the next upcoming Boundary Time Marker instant), populated only when `Settings.boundary_countdown` is on; `state` never changes; `next_prayer` is narrowed to prayer markers permanently. Industry convention checked by websearch: masjid displays count down to the next *prayer*; sunrise/imsak/duha are informational rows (e.g. ISW/Masjidsolutions schedules show Sunrise with no Azaan/Iqama, "Next Prayer" always a prayer; Imsak shown for fasting prep).
5. **Core taxonomy = `MarkerName` + `MarkerKind`** (rename of `PrayerName`), with `marker_kind()` classification and a `Settings` guard banning iqamah rules for boundary markers.
