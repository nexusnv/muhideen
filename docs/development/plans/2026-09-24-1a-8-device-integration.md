## Design Decisions (locked for this slice)

1. **TIME UNSYNCED = port + adapter + engine stamp, mirroring the `stale` precedent** (banner flag rides next-event + SSE state, never a new endpoint). `core/ports.py` gains `runtime_checkable` `TimeSyncProbe.synchronized() -> bool`. `adapters/time_sync.py` `SystemTimeSyncProbe(runner=..., clock=...)`: runs `timedatectl show --property=NTPSynchronized --value` (`yes`/`no`), falls back to `chrony tracking` parse when timedatectl is missing/fails, **fail-closed → False when neither tool exists or both fail**; subprocess result TTL-cached 30s against the injected clock's `monotonic()` (test asserts exactly one runner call inside the TTL). `runner` is an injectable `Callable[[list[str]], str]` so no test ever spawns a real process. Engine ctor gains `time_sync: TimeSyncProbe | None = None` → `None` means `time_synced=True` always (dev/contract/e2e defaults stay green; drift latch not tracked without a probe). With a probe: `time_synced = probe.synchronized() and not latched`. **Drift latch:** compare consecutive stamps — `|(wall_now − wall_prev) − (mono_now − mono_prev)| > 5.0s` against the injected `Clock` (a wall step the monotonic clock didn't see: manual date change / NTP step) → latched; latch clears only when **both** ≥300s of injected monotonic time have elapsed since the step **and** the probe reports True (a probe that keeps saying "synced" through a manual wall step must not clear the banner next tick); probe `False` keeps it latched regardless of age. Engine stamps via `dataclasses.replace(next_event_result, time_synced=...)` in `next_event` (so `tick` inherits it) and adds `event.time_synced` to the `_Fingerprint` tuple (`engine.py:88-99`) → a flip republishes `state` live.
2. **Contract (additive, api stays `v1`, PRD.md:317):** `NextEvent.time_synced: bool = True` appended after `boundary_at` in `core/values.py:115-116` (defaults-only tail preserved — no existing construction sites change); `NextEventDTO.time_synced: bool` (required) + `StateEventDTO.time_synced: bool` (required — SSE `state` frames carry the banner so a display that only holds the stream still renders it; `TickEventDTO` untouched, it is deliberately minimal `now`+`state`). Fixtures updated: `api/fixtures/next-event.json` gains `"time_synced": true`, every `event: state` frame in `events-stream.txt` gains `"time_synced": true` (tick frames unchanged); `docs/api-contract.md` next-event + events examples/prose + Versioning note ("additive `time_synced`, v1 retained"); PRD §6.3 bullet `:312` gains `time_synced`. Existing payload-equality assertions in e2e/contract go **red first** on the DTO change (that is the red evidence) until fixtures/docs are updated; no endpoint, path, query-param, or status-code change → `test_openapi_query_params_match_doc` and the exact-path-set parity untouched.
3. **Entrypoint:** `src/muhideen/service.py` `main(argv: list[str] | None = None) -> None` — argparse only, **no env-var magic** (1A-7 decision 2 precedent): `--db` (default `./muhideen.db`), `--host` (default `127.0.0.1` per PRD.md:327's loopback default), `--port` (default `8000`); zero-arg → `uvicorn.run(create_production_app(args.db), host, port, workers=1)` single worker. The systemd unit passes `--host 0.0.0.0 --port 8000 --db /var/lib/muhideen/muhideen.db` (LAN + FR-6.3 `.local` URL needs `0.0.0.0`). `src/muhideen/seed.py` `main()` → `muhideen-seed --zone SGR01 [--masjid-name …] [--db …]`: if `SettingsRepo.load()` raises `ConfigError` (first boot) → save `Settings(masjid_name=flag or "", zone=--zone, hijri_offset=0)` (required `--zone` in that branch, argparse-level required-ness decided by probing load first — the "create then sync" path), else sync the **configured** zone (a differing `--zone` is a no-op with a logged notice — the installation has one zone, engine `resolve_day` invariant); then `run_sync(client=HttpJAKIMClient…, prayer_repo, settings_repo, clock)` reusing 1A-6 verbatim (its `ConfigError`-propagates contract is what makes the branch split above). `pyproject.toml` `[project.scripts]`: `muhideen = "muhideen.service:main"`, `muhideen-seed = "muhideen.seed:main"`; no dependencies change → `uv.lock` untouched (probe: `uv sync --locked --offline --find-links` exits 0; if `--locked` objectsto the scripts edit, regenerate and amend with a metadata-only-diff note).
4. **`install.sh` (repo root, `bash`, `set -euo pipefail`).** Flags: `--zone ZONE` (drives seed), `--masjid-name NAME` (optional), `--force` (RAM/disk override — PRD.md:321), `--dry-run` (print each step + command, execute nothing except the preflight reads), `--hostname NAME` (default `muhideen` → `hostnamectl set-hostname`; empty string skips — FR-6.3 URL depends on the default). Order: (1) **preflight** — `MemTotal` from `${MUHIDEEN_MEMINFO:-/proc/meminfo}` (<1048576 kB → refuse with override hint unless `--force`) + free-disk via `df` (PATH-shimmed in tests); (2) apt deps `avahi-daemon avahi-utils git curl` (+ `systemd-timesyncd` best-effort); (3) `command -v uv` required — fail fast with install instructions, **never `curl | sh`**; (4) `vendor/wheels/` required — fail fast pointing at `tools/build_vendor.sh`; (5) `uv sync --locked --offline --find-links vendor/wheels` (probe-verified; PRD.md:158's `uv pip install --no-index …` form documented as the fallback in `docs/deployment.md`); (6) `useradd muhideen` (idempotent) + copy `packaging/muhideen.service`/`muhideen-mdns.service` into `${MUHIDEEN_SYSTEMD_DIR:-/etc/systemd/system}` with `sed` prefix substitution for the venv/`ExecStart` path; (7) `.venv/bin/muhideen-seed --zone …`; (8) `chown -R muhideen` on the state dir; (9) `timedatectl set-ntp true` — **warn only on failure** (FR-1.6 makes unsynced visible, it does not make install fail; chrony-only boxes may lack it); (10) `systemctl daemon-reload && systemctl enable --now muhideen muhideen-mdns`; (11) health `curl` `127.0.0.1:8000/api/version` retry loop (≤10s budget → exit 1 with `journalctl -u muhideen` hint on timeout).
5. **`update.sh` (repo root).** Flags: `--check` (print current `git describe` vs newest tag + `/api/version`, exit 0 either way, mutate nothing) and `--dry-run`. Flow: dirty working tree (`git status --porcelain` non-empty) → refuse with stash/commit hint; else **`VACUUM INTO` backup first** (PRD.md:336) via `.venv/bin/python -c` calling `backup_to(Database(db), backups/<tag>-<ts>.db)` — `mkdir -p` the timestamped `backups/` dir first, `backup_to` rejects existing paths by design; then `git fetch --tags && git checkout <tag>` → `uv sync --locked --offline --find-links vendor/wheels` → `systemctl restart muhideen` → health: 20 retries × 0.5s on `127.0.0.1:8000/api/version`; on final failure **exit 1** with a recovery message (previous tag + backup path + `systemctl status` commands) — **no auto-rollback** (deferred, decision 12): a failed health check after a successful resync most often means the device is mid-reboot-side-effect, and a rollback that also fails mid-script leaves no message at all.
6. **mDNS = second unit, no Python dependency.** `packaging/muhideen-mdns.service`: `ExecStart=/usr/bin/avahi-publish-service %H _muhideen._tcp 8000` (FR-4.1; `%H` hostname is the instance name — no config to maintain), `PartOf=muhideen.service` (stops/restarts with the backend), `After=muhideen.service avahi-daemon.service`, `Restart=always`, installed/enabled by the same `install.sh` steps as the main unit. `avahi-daemon` itself comes from apt deps.
7. **Service unit** `packaging/muhideen.service`: `After=network-online.target time-sync.target` + `Wants=network-online.target` (PRD.md:327 — boot-time `TIME UNSYNCED` detection needs time-sync.target reached, synced-or-failed), `Restart=always`, `RestartSec=5`, `User=muhideen`, `Environment=PYTHONUNBUFFERED=1` (journald lines, FR-6.4), `ExecStart=<venv>/bin/muhideen --host 0.0.0.0 --port 8000 --db /var/lib/muhideen/muhideen.db`, `WantedBy=multi-user.target`.
8. **Vendor tooling `tools/build_vendor.sh`** (maintainer machine, network allowed — never runs on device, never in CI): `uv export --no-dev --no-hashes --no-emit-project -o vendor/requirements.txt` (flags probed) → `python -m pip download -r vendor/requirements.txt -d vendor/wheels` (uv has no `pip download`, probed: `unrecognized subcommand`) → **plus `python -m pip download hatchling`** (the `[build-system]` backend — `uv sync --offline` builds the project wheel in isolation and would otherwise miss it) → `uv build` for the project wheel → cross flags `--python-version 3.11 --abi cp311 --only-binary=:all: --platform manylinux_2_17_aarch64|…_x86_64` for aarch64/x86_64; **armv7l deferred to a follow-up issue** (manylinux armv7l wheels for the dependency set are not uniformly published — honest scope, decision 12).
9. **Shared shell `packaging/lib.sh`** sourced by both scripts: `sync_venv()` (the one `uv sync --locked --offline --find-links` invocation, single source of truth) and `health_check()` (retry loop + budget args) — so install and update can never drift apart on the two commands that mutate the environment; unit tests assert both scripts source it.
10. **New `device` test layer** — marker `device` in `pyproject.toml:38-44`, `tests/device/`, row added to `TESTING_STRATEGY.md:7-13`, `:41` sentence flips to "asserted since slice 1A-8". Rules: system unit files parsed with `configparser` + `interpolation=None` (systemd `%H` specifiers would explode default interpolation); scripts run under `bash -n` (syntax) + `--dry-run` (step order/flags) + real runs against **PATH shims** (fake `systemctl`/`curl`/`git`/`timedatectl`/`df`/`apt-get` that append argv to a log file the test reads) with seams `MUHIDEEN_MEMINFO` (fixture file with a chosen `MemTotal`) and `MUHIDEEN_SYSTEMD_DIR` (tmpdir); the entrypoint test spawns the actual `.venv/bin/muhideen` (`Path(sys.executable).with_name("muhideen")`), picks a free port by bind-then-close, polls `/api/version` ≤10.0s (0.1s interval), then `GET /api/next-event` → 200 with `state`/`next_prayer`/`time_synced` present (seeded tmp db with lat/lon → pure-MABIMS calc path, zero network, zero Chromium), finally SIGTERM → clean exit. `time_synced`'s *value* on the runner is environment-dependent (timedatectl may exist but report unsynced) → assert **presence + `bool` type**, not `true`; the deterministic false-path lives in e2e with a stub probe. All device tests run under plain `uv run pytest` (bash on `ubuntu-latest`; no CI workflow edit).
