## Design Decisions (locked for this slice)

1. **Issues #6 and #7 are in-scope acceptance criteria.** #6 lands as `AfterValidator` on the `now` query param (422 for naive, message contains "offset"; probed against the locked FastAPI) plus documented `date`/`zone` input decisions (FastAPI's `date` parsing is inherently strict → 422 on garbage; `zone` gains `Query(min_length=1, max_length=32)`, semantic validity stays the repo's job → unknown zone 404 via `ScheduleError`). #7 lands as an inline `oneOf` of the three SSE DTO `model_json_schema()` outputs under `text/event-stream` content in the route's `responses=` (probed: clean `oneOf`; the `{"model": X}` alternative was rejected — it emits `$ref` + spurious `type: string` and covers only one model). Both issues close when the PR is approved/merged.
2. **Composition root: `create_app(deps: AppDeps) -> FastAPI`, required param, no module-level app.** `AppDeps` = `settings_repo, prayer_repo, display_repo, user_repo, clock, event_bus, database: Database | None = None, run_background: bool = False, jakim_client: JAKIMClient | None = None`. `Engine` + `MabimsCalcEngine` built inside from deps (tz = `deps.clock.now().tzinfo`, `ValueError` if naive — same guard shape as `build_scheduler`). Contract tests never invoke handlers, so each contract file that builds an app defines its own file-local stub deps + FakeClock (rule: doubles stay local); e2e gets real repos over tmp SQLite. `create_production_app(db_path, *, tz=ZoneInfo("Asia/Kuala_Lumpur"), run_background=True)` composes SystemClock/Database/SSEBus/HttpJAKIMClient and returns `create_app(...)` — db_path required, no env-var magic (1A-8 owns the service entrypoint).
3. **Error mapping via two global exception handlers:** `ConfigError → 503`, `ScheduleError → 404`, both `{"detail": str(exc)}` JSON (404 = "the addressed date+zone schedule does not exist"; 503 = "installation not configured/no schedule yet"). `/api/events` computes `engine.next_event(clock.now())` as a precondition before streaming, so the same mapping applies before headers are sent. `ValueError` from settings VO guards in `PUT /api/settings` → 422 (reachable: unpaired `lat`/`lon` passes DTO nullability, VO rejects — named test). `SyncError` deliberately **not** mapped: it is unreachable in the request path (sync runs only in the scheduler, scheduler.py:127-182); 1A-6's deferred "SyncError→HTTP mapping" resolves as not-applicable, recorded in checklist (6).
4. **SSE mechanics:** sync generator (ADR-0001) — subscribe to the `SSEBus` queue first, emit the current `state` frame (fresh `engine.next_event(clock.now())`, `exclude_none=True`), then loop on `queue.get(timeout=_KEEPALIVE_S=60.0)`; `Empty` → yield `: keep-alive\n\n` comment; frames are `event: <name>\ndata: <compact JSON>\n\n`; `state`/`tick` payloads from `engine.next_event`, `config-update` from the carried `changed` tuple (empty → log + drop; `ConfigUpdateEventDTO` mandates `min_length=1`), unknown event names log + drop; `finally: unsubscribe`. Fakes and production share the port; the one ticker daemon (1s cadence, tick-then-wait, swallows `MuhideenError` pre-setup) drives `engine.tick()`.
5. **EventBus port amendment:** `publish(self, event: str, changed: Sequence[str] = ()) -> None` — `config-update` carries its contract payload (`changed` list) through the port; engine call sites unchanged (default arg); `runtime_checkable` isinstance is presence-only so `test_core_ports.py:104` `FullEventBus.publish(event)` stays green (pyright excludes `tests/`); SSEBus stores `(event, changed)` tuples.
6. **Auth: single admin, password-only, in-memory everything.** `UserRepo` port (`has_users()`, `create_user(username, password) -> bool` False-if-exists, `verify(username, password) -> bool`) with argon2id hashing inside `SqliteUserRepo` (crypto lives with the table it protects; port shape mirrors `users`). API keeps `ADMIN_USERNAME = "admin"` and password-only bodies — PRD FR-6.2's wizard collects no username, so no placeholder username appears in the contract. Sessions: `secrets.token_urlsafe(32)` → in-memory dict on `deps.clock.monotonic`, 30-min absolute TTL, cookie `muhideen-session` HttpOnly SameSite=Lax Path=/ (no `Secure` — plain-HTTP LAN, PRD.md:215-216). Rate limit: two `RateLimiter` instances (login, setup) keyed by `request.client.host`, 5 hits / 60s sliding window on `clock.monotonic`, checked **before** password verify (6th attempt = 429 even with the correct password — named test). No dummy-hash timing equalization (LAN-only threat model). `POST /api/auth/setup` allowed only while the users table is empty → else 409; it auto-issues a session cookie so the 1B-3 wizard never forks a login path. PRD's "first-boot forced password change" is satisfied by construction (no default password ever exists); the one-time setup token of FR-6.3 stays B3/1A-8.
7. **`/docs`, `/redoc`, `/openapi.json` gated by one http middleware** (not dependencies, so nothing about the gate interferes with `dependency_overrides` elsewhere): non-LAN → 404 JSONResponse (fail-closed: unparseable scope host, e.g. TestClient's default `"testclient"`, is not LAN), LAN but no valid session → 401; responses are *returned* directly from the middleware (raising `HTTPException` there would escape FastAPI's error envelope). LAN = `ipaddress` `is_private or is_loopback` as a pure function, unit-tested with 8 hosts. `app.openapi()` generated in-process is untouched (contract tests unaffected). TestClient's `client=(host, port)` kwarg (starlette 1.6, probed) supplies LAN/public source IPs in e2e.
8. **Settings API is full-replace PUT, all fields required.** `SettingsDTO` mirrors `Settings` incl. `boundary_countdown` and `calc_only`; `lat`/`lon` are nullable (zone-only installs are legal per migration seeds) with `ge/le` guards; product-pinned bounds cited from PRD (`hijri_offset ±2`, `dim 5–60`), otherwise shape-only guards (positive `adhan_duration_s`, `delay_minutes ≥ 0`, `min/max_length`); `method` narrows to the four FR-1.3 values (`MABIMS, MWL, ISNA, Egyptian` — stored as-is; engine behavior for the latter three unchanged from 1A-6). Successful PUT publishes `("config-update", ("settings",))` on the bus (FR-6.1 live reload). `calc_only` semantics: `run_sync` returns 0 without fetching after its settings load (no retry scheduled); the FR-1.2 resolution order cache→calc→last-known is **not** reordered — calc-only stops the network, it does not demote the cache.
9. **SSE frame absence tests use the sentinel pattern** (publish the invalid event, then a valid one; read until the sentinel; assert the invalid never appeared) — deterministic, no sleeps; the keep-alive test monkeypatches module const `_KEEPALIVE_S` to 0.05; the unsubscribe test polls ≤1s because teardown runs in a worker thread.
10. **Background lifecycle:** ticker thread (name `muhideen-ticker`, daemon) and scheduler thread (name `muhideen-scheduler`, daemon, `target=scheduler.start`, blocks) start only when `run_background=True`; shutdown: `stop.set()` + `ticker.join(2.0)` + `scheduler_thread.join(0.5)` (lets `start()` win the start/shutdown race) + `if scheduler.running: scheduler.shutdown(wait=False)` (no `SchedulerNotRunningError` import needed) + `display_repo.flush()`. Tests that boot background wiring inject a file-local fake `JAKIMClient` — zero network even if the 02:00 cron fires mid-suite.
11. **No ADR.** In-memory sessions/limiter are swappable internals (the cookie contract is stable), argon2 is PRD-mandated, the single-worker limiter premise follows ADR-0001, and the contract diff is additive (no `/api/v2`, `api-contract.md:68-71`).
